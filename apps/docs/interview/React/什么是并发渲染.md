# 什么是并发渲染？

:::tip 一句话总结
并发渲染是 React 的异步可中断渲染机制。它通过时间切片把 `render` 工作拆成可调度的小任务，在任务间隙让出主线程，并让高优先级更新优先响应，从而在复杂更新下保持交互流畅。
:::

## 要点拆解

### render 阶段可中断

React 的更新分为 render 和 commit 两个阶段。render 只在内存中做计算，不直接改 DOM，所以可以被中断、恢复或重做；commit 才真正修改 DOM，上屏时必须同步完成。

### 时间切片让出主线程

时间切片指的是 React 不一次性执行完较大的 render 工作，而是分段处理任务。每执行一段，就有机会把主线程还给浏览器，让输入、点击、绘制等任务先被处理。

### 优先级调度决定先响应谁

React 用 `lane` 表示更新优先级。点击、输入这类交互优先级更高，`startTransition` 里的更新优先级更低。当低优先级 render 遇到高优先级更新时，React 会优先处理更紧急的更新。

## 优先级相关 API

- `startTransition`：把更新标记为非紧急更新，让输入、点击等高优先级更新先响应；
- `useTransition`：在发起 transition 的同时拿到 `isPending`，用于展示低优先级更新的过渡状态；
- `useDeferredValue`：延后使用变化频繁的值，让当前交互先保持流畅；
- `Suspense`：和并发渲染配合，在内容未准备好时展示 `fallback`，避免阻塞已经可响应的界面。

::: danger 注意
并发渲染不保证每次 render 都会提交，render 也可能被打断后重新执行。所以 render 阶段必须保持纯净，不能发请求、订阅、修改 DOM 或写外部变量；副作用应该放到 `useEffect`、`useLayoutEffect` 或事件处理里。
:::
