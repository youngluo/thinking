# Agent 应用中的流处理

Agent 请求往往要经过多轮模型调用，期间还会穿插检索、工具执行和最终响应生成。如果等所有步骤完成后再返回，用户在这段时间里看不到进展。流式处理让服务端在执行过程中持续发送事件，前端可以边接收边更新回答和执行状态。这些事件不只包含模型文本增量，也包括检索和工具调用状态、工具参数与结果、错误和结束信号。

本文的服务端代码统一使用 Next.js App Router 的 Route Handler 作为 HTTP 入口，便于展示请求、响应、流和取消信号如何衔接。这个选择只影响示例入口，流处理本身不依赖 Next.js，独立 Node.js 服务也可以采用同样的事件分层和转换逻辑。

## 什么是流

流（stream）是一种增量传输数据的抽象。数据生产方可以在产生一部分数据后立即发送，消费方则在片段到达时逐个处理，不必等待完整结果。普通响应通常要等结果生成完成后，才将完整响应交给消费方。

流描述的是数据如何到达，不规定数据的具体内容或编码。SSE 负责定义网络上的消息格式，Web Streams 和 Node.js Streams 则提供在代码中读取、写入和转换这些数据的 API。本文先区分两套运行时 API，再说明数据如何从网络片段转换成业务事件。

### Node.js Streams

Node.js Streams 是 Node.js 运行时中的流 API，核心类型包括 `Readable`、`Writable`、`Duplex` 和 `Transform`。

- `Readable` 表示可读取的数据源；
- `Writable` 表示可写入的目标；
- `Duplex` 同时支持读取和写入；
- `Transform` 是一种可以处理并转换数据的双工流。

Node.js Streams 主要用于文件、网络连接和进程输入输出。可读流通常通过 `pipe()` 连接到其它流，也可以通过 `for await...of` 按块消费。它与 Web Streams 的职责相近，但类型和方法不同；需要互操作时，Node.js 提供 `Readable.fromWeb()` 和 `Readable.toWeb()`。

### Web Streams

Web Streams API 是 Web 平台提供的流 API，核心类型包括 `ReadableStream`、`WritableStream` 和 `TransformStream`。

- `ReadableStream` 用于逐段读取数据；
- `WritableStream` 用于逐段写入数据；
- `TransformStream` 用于在读取和写入之间转换数据。

客户端通过 `fetch` 发起请求后，`response.body` 就是一个 `ReadableStream<Uint8Array>`。读取时先通过 `getReader()` 获取读取器，再调用 `reader.read()` 取得数据片段。`done` 表示流是否结束，`value` 是 `Uint8Array`，需要用 `TextDecoder` 将 `value` 解码成文本：

```ts fold
const response = await fetch('/api/chat')
const reader = response.body.getReader()
const decoder = new TextDecoder()
const { value, done } = await reader.read()
const text = done ? decoder.decode() : decoder.decode(value, { stream: true })
```

一次读取只代表当前可用的字节，不保证对应完整消息。连续读取时要复用同一个 `TextDecoder`，中间片段使用 `{ stream: true }` 保留未完成的字节，流结束时再调用 `decode()` 清空内部缓冲。

## 流数据的处理层次

流处理不是所有链路都经过同样的层次。可以先把数据从网络到 UI 的变化拆开：

| 层次             | 说明                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 网络片段         | `reader.read()` 返回的 `value` 是本次读取到的字节，不保证对应一条完整消息。          |
| 文本片段         | `TextDecoder` 解码后的文本，仍可能只包含半条消息或多条消息的一部分。                 |
| 协议事件（可选） | 按 SSE 空行边界拼出的完整事件，`event` 名称由发送方约定。                            |
| 业务事件         | 将供应商返回的字段映射为应用统一的事件类型，例如文本增量、工具状态、错误和结束信号。 |
| UI 状态          | 业务事件处理器根据事件类型更新界面，例如追加回答、更新状态、展示错误或完成收尾。     |

不同接入方式经过的处理层次不同：

- 客户端调用模型 API 通常直接消费供应商的协议事件或响应字段，可以不用映射业务事件；
- 服务端中转会把供应商事件映射成前端约定的业务事件；
- SDK 或 LangChain 已经返回结构化事件时，可以跳过协议解析，直接映射成业务事件。

## 封装 SSE 流处理方法

后面的服务端示例都会涉及字节解码、SSE 事件组装和响应生命周期。将这些逻辑封装成可复用函数后，业务代码只需读取上游事件、转换字段并写出业务事件。函数只解析本文约定的 `event` 字段，以及 `data` 字段中的 JSON 内容，不覆盖完整的 SSE 规范。

三个函数的职责如下：

| 函数                | 职责                                                               |
| ------------------- | ------------------------------------------------------------------ |
| `parseSSE`          | 把 `ReadableStream` 解析成 SSE 事件流，调用方用 `for await` 消费。 |
| `writeSSE`          | 服务端往 `controller` 写一条 SSE 事件。                            |
| `createSSEResponse` | 包装一个标准的 SSE `Response`，自动处理取消、错误和结束信号。      |

下面是具体的代码实现：

<Tabs>
<Tab label="parseSSE">

```ts fold
export async function* parseSSE(body: ReadableStream<Uint8Array>) {
  const reader = body.getReader()
  const decoder = new TextDecoder()
  let buffer = ''
  let finished = false

  try {
    while (true) {
      const { value, done } = await reader.read()

      if (done) {
        buffer += decoder.decode()
        finished = true
        break
      }

      buffer += decoder.decode(value, { stream: true })
      const blocks = buffer.split(/\r?\n\r?\n/)
      buffer = blocks.pop() ?? ''

      for (const block of blocks) {
        const lines = block.split(/\r?\n/)
        const event =
          lines
            .find((line) => line.startsWith('event:'))
            ?.slice('event:'.length)
            .trim() || 'message'
        const data = lines
          .filter((line) => line.startsWith('data:'))
          .map((line) => line.slice('data:'.length).replace(/^ /, ''))
          .join('\n')

        if (data) {
          yield { event, data }
        }
      }
    }
  } finally {
    if (!finished) {
      try {
        await reader.cancel()
      } catch {
        // 流已经出错或被取消时，cancel 可能再次失败。
      }
    }
    reader.releaseLock()
  }
}
```

```ts fold
export function createSSEResponse(
  request: Request,
  produce: (
    controller: ReadableStreamDefaultController<Uint8Array>,
    signal: AbortSignal
  ) => Promise<void>
) {
  const abortController = new AbortController()
  const handleAbort = () => abortController.abort()

  if (request.signal.aborted) {
    handleAbort()
  } else {
    request.signal.addEventListener('abort', handleAbort, { once: true })
  }

  const stream = new ReadableStream({
    async start(controller) {
      try {
        await produce(controller, abortController.signal)
        if (!abortController.signal.aborted) {
          writeSSE(controller, 'done', {})
        }
      } catch (error) {
        if (!abortController.signal.aborted) {
          const message = error instanceof Error ? error.message : '执行失败'
          writeSSE(controller, 'error', { message })
        }
      } finally {
        request.signal.removeEventListener('abort', handleAbort)
        if (!abortController.signal.aborted) {
          controller.close()
        }
      }
    },
    cancel() {
      abortController.abort()
    },
  })

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream; charset=utf-8',
      'Cache-Control': 'no-cache, no-transform',
    },
  })
}
```

## 客户端调用模型 API

客户端直接调用模型 API 是最简单的流处理链路。客户端使用 `parseSSE` 解析响应体中的 SSE 事件，再从返回数据中提取文本增量并更新界面。示例中的 `apiKey` 和 `model` 由用户在本地配置。

```ts fold
import { parseSSE } from '@/lib/sse'

const response = await fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ model, messages, stream: true }),
})

if (!response.ok) {
  throw new Error(`模型请求失败：${response.status}`)
}

if (!response.body) {
  throw new Error('模型响应体为空')
}

for await (const { data } of parseSSE(response.body)) {
  if (data === '[DONE]') break

  const payload = JSON.parse(data)
  const content = payload.choices?.[0]?.delta?.content
  if (content) appendAssistantText(content)
}
```

它适合 demo，也适合由用户自行管理 API Key 的本地 Agent。其它场景通常应优先通过服务端中转，由服务端统一管理密钥、鉴权、请求控制和供应商协议适配，避免 API Key 暴露在客户端。

## 服务端中转模型 API

服务端中转会先接收客户端请求，再调用模型 API，并将上游流转换为前端约定的业务事件。密钥、鉴权和请求控制也统一在这一层处理。后面的服务端示例统一使用 `OPENAI_API_KEY` 和 `OPENAI_MODEL` 配置 API Key 与模型名称。

下面是一个简化的 HTTP POST 处理函数。

```ts fold title="app/api/chat/route.ts"
import { createSSEResponse, parseSSE, writeSSE } from '@/lib/sse'

export async function POST(request: Request) {
  const { messages } = await request.json()

  return createSSEResponse(request, async (controller, signal) => {
    const response = await fetch('https://api.openai.com/v1/chat/completions', {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${process.env.OPENAI_API_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: process.env.OPENAI_MODEL!,
        messages,
        stream: true,
      }),
      signal,
    })

    if (!response.ok) {
      throw new Error(`模型请求失败：${response.status}`)
    }

    if (!response.body) {
      throw new Error('模型响应体为空')
    }

    for await (const { data } of parseSSE(response.body)) {
      if (data === '[DONE]') break

      const payload = JSON.parse(data)
      const content = payload.choices?.[0]?.delta?.content
      if (content) writeSSE(controller, 'message', { content })
    }
  })
}
```

这个处理函数读取 OpenAI Chat Completions API 返回的 SSE，提取 `choices[0].delta.content` 字段，再用 `writeSSE` 写出稳定的 `message` 事件。客户端断开、结束和错误等生命周期逻辑由 `createSSEResponse` 统一处理。这样前端无需依赖 `delta`、`content`、`choices` 等上游字段，后续切换模型或接入 Agent 工具时只需替换上游调用和字段映射。

## 服务端通过 OpenAI SDK 调用模型

如果不想手写请求体、鉴权头和流式响应解析，可以使用 OpenAI 官方 Node SDK。SDK 会将 Responses API 的流式响应转换为带类型的事件，业务代码只需处理需要关注的事件。

```ts fold title="app/api/chat/route.ts"
import OpenAI from 'openai'
import { createSSEResponse, writeSSE } from '@/lib/sse'

const client = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
})

export async function POST(request: Request) {
  const { messages } = await request.json()

  return createSSEResponse(request, async (controller, signal) => {
    const stream = await client.responses.create(
      {
        model: process.env.OPENAI_MODEL!,
        input: messages,
        stream: true,
      },
      { signal }
    )

    for await (const event of stream) {
      if (event.type === 'response.output_text.delta') {
        writeSSE(controller, 'message', { content: event.delta })
      }

      if (event.type === 'response.failed') {
        throw new Error(event.response.error?.message ?? '模型生成失败')
      }

      if (event.type === 'error') {
        throw new Error(event.message)
      }
    }
  })
}
```

SDK 将流式响应包装成 `AsyncIterable`。这个示例只处理文本增量和失败事件，前者转换为应用统一的 `message` 事件，后者交给 `createSSEResponse` 统一处理。接入工具调用时，只需继续映射相应的 Responses 事件，前端仍可使用同一套业务事件协议。

## 服务端通过 LangChain 调用模型

前两种写法都直接依赖供应商 API。需要统一模型调用方式，或继续接入工具与多步 Agent 时，可以引入 LangChain。LangChain 提供统一的模型调用接口，服务端只需将模型返回的文本增量转换为 `message` 事件。切换供应商时只需更换对应的集成类和配置，前端的流式消费方式保持不变。

```ts fold title="app/api/chat/route.ts"
import { ChatOpenAI } from '@langchain/openai'
import { createSSEResponse, writeSSE } from '@/lib/sse'

const model = new ChatOpenAI({
  apiKey: process.env.OPENAI_API_KEY,
  model: process.env.OPENAI_MODEL!,
})

export async function POST(request: Request) {
  const { messages } = await request.json()

  return createSSEResponse(request, async (controller, signal) => {
    const modelStream = await model.stream(messages, { signal })

    for await (const chunk of modelStream) {
      if (chunk.text) {
        writeSSE(controller, 'message', { content: chunk.text })
      }
    }
  })
}
```

`model.stream()` 返回模型的增量输出。示例将其中的非空文本转换为 `message` 事件，结束、错误和取消仍由 `createSSEResponse` 统一处理。与上一节相比，只有上游模型调用方式发生变化，中转层的业务事件协议保持不变。

## 客户端消费业务事件流

服务端中转层会把原始 API、SDK 或 LangChain 返回的结果转换成业务事件，客户端只需按约定处理这些事件。Agent 流通常包含以下事件：

| 事件类型      | 含义               | 前端行为               |
| ------------- | ------------------ | ---------------------- |
| `message`     | 模型文本增量       | 追加到回答区域         |
| `tool_call`   | 工具调用开始或更新 | 展示工具调用状态       |
| `tool_result` | 工具执行结果       | 展示结果或折叠详情     |
| `status`      | Agent 当前执行状态 | 更新状态文案           |
| `error`       | 生成或执行失败     | 展示错误并结束加载状态 |
| `done`        | 流结束             | 收尾并允许继续输入     |

这些事件不能全部按文本拼接。以文本流接口为例，前端只需处理 `message`、`error` 和 `done` 三类事件。

```js fold
function handleAgentEvent(event) {
  switch (event.type) {
    case 'message':
      appendAssistantText(event.content)
      break

    case 'error':
      showError(event.message)
      finishStreaming()
      break

    case 'done':
      finishStreaming()
      break
  }
}
```

### 用 EventSource 消费 SSE

`EventSource` 通过 GET 建立服务端到浏览器的单向 SSE 连接，并按 `event:` 名称自动分发事件。它适合不需要 POST body 或自定义请求头的场景。示例沿用 `/api/chat`，服务端需要在同一路由中提供 GET 处理函数，并通过会话 ID 读取已保存的上下文。

```ts fold
const source = new EventSource(
  `/api/chat?sessionId=${encodeURIComponent(sessionId)}`
)

source.addEventListener('message', (e) => {
  handleAgentEvent({ type: 'message', ...JSON.parse(e.data) })
})

source.addEventListener('done', () => {
  handleAgentEvent({ type: 'done' })
  source.close()
})

source.addEventListener('error', (e) => {
  if (e instanceof MessageEvent && e.data) {
    handleAgentEvent({ type: 'error', ...JSON.parse(e.data) })
    source.close()
    return
  }

  handleAgentEvent({ type: 'error', message: '连接异常' })
  // 普通连接异常不主动 close，让 EventSource 按浏览器策略自动重连。
})
```

使用 `EventSource` 时要注意以下行为：

- 默认事件名是 `message`，自定义事件（如 `done`、`tool_call`）必须显式 `addEventListener` 才能收到；
- 这里把业务错误也命名为 `error`，监听器会同时收到服务端发送的 `MessageEvent` 和连接异常产生的普通 `Event`，需要根据 `data` 区分；
- 普通连接异常后浏览器会自动重连；流正常结束或服务端已返回业务错误时，再手动调用 `close()`。

### EventSource 的自动重连机制

`EventSource` 的连接因网络抖动、代理断开或服务端临时异常而中断时，浏览器会触发 `error` 事件。只要没有调用 `source.close()`，浏览器就会等待一段时间后重新请求同一地址。

服务端可以用 `retry:` 字段设置后续重连间隔，单位为毫秒：

```text
retry: 3000

event: message
data: {"content":"hi"}
```

空行用于结束当前 SSE 事件块。这里只有 `retry:`，因此不会触发业务事件；后面的 `message` 是下一条事件。服务端不发送 `retry:` 时，浏览器使用自身的默认重连间隔。

服务端还可以用 `id:` 标记事件，浏览器会记录最后收到的事件 ID：

```text
id: 42
event: message
data: {"content":"hi"}
```

重新连接时，浏览器会通过 `Last-Event-ID` 请求头带回该值。服务端可以据此从断点继续推送，但必须自行保存事件历史或进度；浏览器只负责回传事件 ID。

### 用 fetch 消费 SSE

`EventSource` 只支持 GET，且不能直接携带自定义请求头。Chat 或 Agent 接口通常需要通过 POST body 传递消息，并携带鉴权信息和请求上下文，此时可以用 `fetch` 发起请求，再通过 `parseSSE` 解析响应流。

```js fold
import { parseSSE } from '@/lib/sse'

const response = await fetch('/api/chat', {
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ messages }),
  method: 'POST',
})

if (!response.ok) {
  handleAgentEvent({ type: 'error', message: `请求失败：${response.status}` })
  return
}

if (!response.body) {
  handleAgentEvent({ type: 'error', message: '响应体为空' })
  return
}

for await (const { event, data } of parseSSE(response.body)) {
  const payload = JSON.parse(data)
  handleAgentEvent({ ...payload, type: event })
}
```

`parseSSE` 负责字节读取、跨 chunk 拼接和 SSE 事件解析。调用方只需解析 JSON，再将业务事件交给 `handleAgentEvent`。

### 用 Axios 消费 SSE

如果项目已经使用 Axios，可以通过 `onDownloadProgress` 读取响应文本。Axios 负责请求配置和错误处理，SSE 事件拼接仍由业务代码完成。

```js fold
import axios from 'axios'

let readOffset = 0
let buffer = ''

function handleSSEBlock(block) {
  const lines = block.split(/\r?\n/)
  const event =
    lines
      .find((line) => line.startsWith('event:'))
      ?.slice('event:'.length)
      .trim() || 'message'
  const data = lines
    .filter((line) => line.startsWith('data:'))
    .map((line) => line.slice('data:'.length).replace(/^ /, ''))
    .join('\n')

  if (!data) return

  const payload = JSON.parse(data)
  handleAgentEvent({ ...payload, type: event })
}

function consumeResponseText(responseText) {
  const chunk = responseText.slice(readOffset)
  readOffset = responseText.length

  buffer += chunk
  const blocks = buffer.split(/\r?\n\r?\n/)
  buffer = blocks.pop() ?? ''

  for (const block of blocks) {
    if (block.trim()) handleSSEBlock(block)
  }
}

try {
  await axios.post(
    '/api/chat',
    { messages },
    {
      responseType: 'text',
      onDownloadProgress({ event }) {
        consumeResponseText(event.target.responseText)
      },
    }
  )
} catch {
  handleAgentEvent({ type: 'error', message: '请求失败' })
}
```

`onDownloadProgress` 中的 `event.target` 是底层 `XMLHttpRequest`。由于 `responseText` 会不断累积，每次回调只截取新增内容，并把不完整的 SSE 事件留在 `buffer` 中等待下一段数据。Axios 会对下载进度回调进行节流，因此文本增量可能成批到达；如果项目没有依赖 Axios 的实例配置或拦截器，原生 `fetch` + `parseSSE` 更直接。

## 流处理的工程实践

`parseSSE`、`writeSSE` 和 `createSSEResponse` 已封装字节、协议与生命周期处理，业务代码仍要关注部署链路和运行时边界。反向代理、负载均衡器或托管平台可能缓冲响应，导致服务端持续写入，客户端却迟迟收不到事件。部署时应确认整条链路支持流式传输，并关闭代理缓冲。使用 Nginx 时，服务端可以返回 `X-Accel-Buffering: no` 响应头，关闭当前响应的代理缓冲。

工具调用期间如果长时间没有业务事件，还应发送心跳，并检查各层的空闲超时设置。SSE 注释行不会触发业务事件，可用作心跳，例如 `: ping\n\n`。

### 处理用户取消和连接关闭

用户停止生成或关闭页面时，前端应通过 `AbortController` 取消请求，服务端也要感知连接关闭并中止上游调用，避免模型继续生成或向已关闭的连接写入数据。

`createSSEResponse` 会把 `request.signal` 桥接到内部 `AbortController`，并在响应流取消时调用 `abort()`。业务代码只需将 `signal` 透传给上游 `fetch` 或 `model.stream(..., { signal })`。

### 将错误作为事件返回

流式接口的错误可能发生在响应开始前或传输过程中。请求校验、鉴权失败等已知错误应在流开始前通过 HTTP 状态码返回；响应开始后，状态码已经发出，上游模型断开或工具超时等错误只能转换成前端可识别的事件。

```json
{ "type": "error", "message": "模型连接中断" }
```

前端收到 `error` 事件后，应停止加载、展示原因并允许用户重试。`createSSEResponse` 会在 `produce` 抛错时写出该事件，业务代码只需保留具体的错误上下文。

## 总结

Agent 应用中的流处理是一条端到端链路。服务端读取模型输出，完成协议解析和字段映射，再向客户端发送稳定的业务事件。客户端只需按事件类型更新文本、工具状态、错误和完成状态。模型 API、SDK 或框架可以替换，只要业务事件协议保持稳定，前端消费逻辑就无需随上游变化。

实现这条链路时，需要区分网络 chunk、协议事件和业务事件，不能把一次读取结果当成完整消息。用户取消、流内错误、代理缓冲、心跳和连接超时也要贯穿前后端处理，确保事件及时到达，并在取消、错误或超时时正确结束连接。
