# 日志采集

前端日志记录异常、行为、接口结果和运行环境，也可与性能指标共用上报入口。要还原线上问题，日志需要关联页面与时间，并避免采集不必要的敏感信息。

## 错误日志

同步脚本错误和资源加载失败都可通过 `error` 事件采集，但要按事件目标区分字段；框架边界捕获到错误后还要显式上报。

### 采集指标

| 类型                  | 描述                                                     |
| --------------------- | -------------------------------------------------------- |
| JavaScript 运行时错误 | SyntaxError、TypeError、ReferenceError 等                |
| 资源加载失败          | 图片、脚本、样式等加载失败；示例不采集 HTTP 状态码       |
| Promise 未捕获异常    | `unhandledrejection` 捕获的拒绝                           |
| 框架层错误            | React Error Boundary、Vue `errorCaptured` 等回调捕获的错误 |

React Error Boundary 不捕获事件处理器和定时器等异步回调中的错误，这类错误应在对应代码路径中处理。边界捕获到的组件错误可在 `componentDidCatch` 中上报，详见 [React 官方文档](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)。开发环境中，已捕获的错误也可能冒泡到 `window`，接入全局监听时应避免重复上报。

### 采集方案

```js fold
// JS 运行时错误 + 资源加载失败
window.addEventListener(
  'error',
  (e) => {
    // 资源错误的 target 是对应元素，脚本运行错误的 target 是 window。
    if (e.target !== window) {
      const target = e.target
      const url = target instanceof Element
        ? target.getAttribute('src') || target.getAttribute('href')
        : undefined
      report({
        type: 'resource-error',
        path: location.pathname,
        url: url ? safePageUrl(url) : undefined,
      })
    } else {
      report({
        path: location.pathname,
        stack: e.error?.stack,
        filename: e.filename ? safePageUrl(e.filename) : undefined,
        lineno: e.lineno,
        type: 'js-error',
        colno: e.colno,
        msg: e.message,
      })
    }
  },
  // 资源加载错误不会冒泡，因此要在捕获阶段监听。
  true
)

// Promise 未捕获异常
window.addEventListener('unhandledrejection', (e) => {
  // reason 可能是任意值，转成字符串后再上报，避免直接传入对象。
  const reason = e.reason
  report({
    msg: reason instanceof Error ? reason.message : String(reason),
    type: 'unhandledrejection',
    path: location.pathname,
    stack: reason instanceof Error ? reason.stack : undefined,
  })
})
```

## 行为日志

行为事件按页面访问和会话归并。路由变化会开始新的页面访问，停留时长只累计页面可见的区间。

### 采集指标

| 类型       | 统计口径                                                                                               | 触发方式               |
| ---------- | ------------------------------------------------------------------------------------------------------ | ---------------------- |
| PV / UV    | PV 按 `page_view` 事件计数；UV 在统计周期内按匿名访客标识去重                                          | 首次加载、路由变化     |
| 停留时长   | 按 `viewId` 取每次访问最新的 `page_hidden.duration`（累计可见时长），再求平均                            | 路由变化、页面隐藏     |
| 点击热区   | 按 `element`、`xRatio`、`yRatio` 统计点击分布                                                           | 事件代理               |
| 页面跳出率 | 本文按单页会话口径计算：只产生一次 `page_view` 的会话数 / 会话总数；会话边界按统计系统规则划分          | 按会话归并页面浏览事件 |

### 采集方案

下面的示例覆盖首次访问、History API 路由变化和浏览器前后台切换，并通过 [`visibilitychange`](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event) 暂停或恢复页面计时。

```js fold
let currentPage = null

const reportPageHidden = () => {
  if (!currentPage) return

  if (currentPage.visibleAt !== null) {
    // 只结算尚未计入的可见区间，避免重复累计。
    currentPage.visibleDuration += performance.now() - currentPage.visibleAt
    currentPage.visibleAt = null
  }

  report({
    id: currentPage.hiddenId,
    type: 'page_hidden',
    path: currentPage.path,
    viewId: currentPage.viewId,
    duration: Math.round(currentPage.visibleDuration),
    time: Date.now(),
  })
}

const reportPageView = (path) => {
  // 同一路径的状态更新不算新的页面访问。
  if (currentPage?.path === path) return
  reportPageHidden()

  currentPage = {
    path,
    viewId: crypto.randomUUID(),
    hiddenId: crypto.randomUUID(),
    visibleDuration: 0,
    visibleAt: document.visibilityState === 'visible' ? performance.now() : null,
  }

  report({
    type: 'page_view',
    path,
    viewId: currentPage.viewId,
    time: Date.now(),
  })
}

const getRoutePath = () => location.pathname
reportPageView(getRoutePath())

// pushState 和 replaceState 不会触发 popstate，需要在调用后补记路由变化。
;['pushState', 'replaceState'].forEach((method) => {
  const original = history[method]
  history[method] = function (...args) {
    const result = original.apply(this, args)
    reportPageView(getRoutePath())
    // 保留原 History API 的返回值。
    return result
  }
})

window.addEventListener('popstate', () => reportPageView(getRoutePath()))

// 页面隐藏时暂停计时，重新可见时从当前时刻继续累计。
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    reportPageHidden()
  } else if (currentPage?.visibleAt === null) {
    currentPage.visibleAt = performance.now()
  }
})

// 点击热区
document.addEventListener('click', (e) => {
  // 向上查找最近的采集标记，只记录显式声明的元素。
  const element = e.target
  if (!(element instanceof Element)) return
  const target = element.closest('[data-report]')
  if (!target) return

  const rect = target.getBoundingClientRect()
  if (rect.width === 0 || rect.height === 0) return

  report({
    type: 'click',
    path: currentPage?.path ?? getRoutePath(),
    time: Date.now(),
    element: target.dataset.report,
    // 将点击位置换算为元素内 0 到 1 的相对坐标。
    xRatio: Math.min(1, Math.max(0, (e.clientX - rect.left) / rect.width)),
    yRatio: Math.min(1, Math.max(0, (e.clientY - rect.top) / rect.height)),
  })
})
```

对于示例监听器未覆盖的路由变化（如 hash 路由），应从框架路由回调调用 `reportPageView()`。如果 query 或 hash 用来区分页面，回调应传入规范化后的路由标识，点击日志也使用同一标识。例如将 `/users/123` 映射为 `/users/:id`，避免记录具体用户标识，并把同类访问归并统计。

## 接口日志

接口日志用于统计成功率、响应耗时和状态码分布，并定位失败原因。通常记录请求路径、耗时、HTTP 状态码及必要的错误码。请求体和响应体可能含敏感信息，默认不采集；如确需采集，应按字段白名单筛选后再上报。

### 采集指标

| 类型         | 描述                 |
| ------------ | -------------------- |
| 接口成功率   | 2xx 响应数 / 未主动取消的已采集请求数 |
| 接口响应时间 | P50 / P95 / P99 分布 |
| 接口状态码   | 2xx / 4xx / 5xx 占比 |

### 采集方案

```js fold
// 保存请求开始时间，供响应拦截器计算耗时。
axios.interceptors.request.use((config) => {
  config.metadata = { ...config.metadata, startTime: performance.now() }
  return config
})

axios.interceptors.response.use(
  (response) => {
    const { config } = response
    const startTime = config.metadata?.startTime
    report({
      duration: startTime == null ? undefined : performance.now() - startTime,
      url: config.url?.split('?')[0],
      status: response.status,
      type: 'api_success',
    })
    return response
  },
  (error) => {
    // 主动取消的请求不计入接口失败。
    if (axios.isCancel(error)) return Promise.reject(error)

    const config = error.config
    // 请求配置可能不存在，例如请求在发出前就失败。
    const startTime = config?.metadata?.startTime

    report({
      duration: startTime == null ? undefined : performance.now() - startTime,
      url: config?.url?.split('?')[0],
      status: error.response?.status,
      code: error.code,
      type: 'api_error',
    })
    return Promise.reject(error)
  }
)
```

耗时用 `performance.now()` 计算，不受系统时钟调整影响。主动取消不计为失败；示例只记录去掉查询参数的请求路径，线上还应将动态路径映射为模板。没有 HTTP 响应的网络错误无法记录状态码。

## 环境日志

环境字段用于判断错误是否集中在特定浏览器、系统或视口。只采集排查所需信息，不把原始 UA 当作稳定身份标识。浏览器可能删减 UA 中的设备型号、系统版本或次版本号，因此解析结果只适合粗略定位，详见 [UA 降噪说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/User-agent_reduction)。

### 采集指标

| 类型            | 描述                               | 采集方式                        |
| --------------- | ---------------------------------- | ------------------------------- |
| 浏览器类型/版本 | Chrome、Firefox、Safari 等及版本号 | UA 解析                         |
| 操作系统        | iOS、Android、Windows、macOS       | UA 解析                         |
| 屏幕与视口      | 屏幕尺寸、视口尺寸和 DPR           | `window.screen`、`innerWidth`、`innerHeight` |

### 采集方案

```js fold
const ua = navigator.userAgent
// parseUA 和 parseOS 由项目使用的 UA 解析库提供。
const browser = parseUA(ua)
const screen = window.screen

const getEnvInfo = () => ({
  browser: browser.name + ' ' + browser.version,
  screen: screen.width + 'x' + screen.height,
  viewport: window.innerWidth + 'x' + window.innerHeight,
  dpr: window.devicePixelRatio,
  os: parseOS(ua),
})
```

## 日志上报策略

各类日志和性能指标统一通过 `report()` 进入缓冲。每次文档加载生成一个 `pageId`，每条可更新的日志有独立 `id`；更新页面停留时间或指标时复用原 `id`。接收端以 `pageId` 和 `id` 作为幂等键，避免重复计数。访客和会话标识按统一的隐私规则生成。

### 批量上报

下面的示例在浏览器入口初始化一次，每累计 20 条或每隔 3 秒发送一批日志，页面隐藏时也会尝试发送。`crypto.randomUUID()` 需要 HTTPS 或 localhost 环境。

[Beacon API](https://www.w3.org/TR/beacon/) 的 `navigator.sendBeacon()` 适合发送少量、无需等待响应的日志，也不会阻塞页面。`flush()` 会先尝试用它发送当前批次。

```js fold
const logBuffer = new Map()
const pageId = crypto.randomUUID()
let isFlushing = false

const MAX_BUFFER_ENTRIES = 200
const MAX_BATCH_BYTES = 48 * 1024
const FLUSH_THRESHOLD = 20
const sensitiveKey = /(?:phone|email|password|pwd|token|secret|api[_-]?key|cookie|authorization)/i

function sanitize(value) {
  if (value instanceof Error) {
    // Error 的字段通常不可枚举，显式提取后才能序列化。
    return { name: value.name, message: value.message, stack: value.stack }
  }
  if (Array.isArray(value)) return value.map(sanitize)
  if (!value || typeof value !== 'object') return value

  return Object.fromEntries(
    Object.entries(value).map(([key, item]) => [
      key,
      sensitiveKey.test(key) ? '[filtered]' : sanitize(item),
    ])
  )
}

function safePageUrl(value = location.href) {
  try {
    const url = new URL(value, location.origin)
    // 只记录 HTTP(S) 地址，避免把 data: 等内嵌内容写入日志。
    if (url.protocol !== 'http:' && url.protocol !== 'https:') return undefined
    // 去掉查询参数和片段，避免把其中的内容带入日志。
    return url.origin + url.pathname
  } catch {
    return undefined
  }
}

/** 缓存记录，同一标识的后续结果覆盖旧值。 */
function report(data) {
  const entry = sanitize({
    ...data,
    id: data.id ?? crypto.randomUUID(),
    pageId,
    pageUrl: safePageUrl(data.pageUrl),
    time: data.time ?? Date.now(),
  })

  // 缓冲满时丢弃最早记录，避免网络故障导致内存持续增长。
  if (!logBuffer.has(entry.id) && logBuffer.size >= MAX_BUFFER_ENTRIES) {
    const oldestId = logBuffer.keys().next().value
    logBuffer.delete(oldestId)
  }
  logBuffer.set(entry.id, entry)
  if (logBuffer.size >= FLUSH_THRESHOLD) flush()
}

async function flush() {
  // 防止定时器和页面隐藏事件同时发送同一批记录。
  if (isFlushing || logBuffer.size === 0) return
  isFlushing = true

  try {
    const batch = []
    let batchBytes = 2 // JSON 数组的方括号。

    for (const [id, entry] of logBuffer) {
      const json = JSON.stringify(entry)
      const itemBytes = new Blob([json]).size + (batch.length ? 1 : 0)

      if (batchBytes + itemBytes > MAX_BATCH_BYTES) {
        if (batch.length > 0) break

        // 单条记录超出上限时跳过，避免它阻塞后续日志。
        logBuffer.delete(id)
        continue
      }

      batch.push({ id, entry, json })
      batchBytes += itemBytes
    }

    if (batch.length === 0) return

    const payload = new Blob([`[${batch.map(({ json }) => json).join(',')}]`], {
      type: 'application/json',
    })
    const queued = navigator.sendBeacon?.('/analytics', payload)

    // Beacon 返回 true 只表示浏览器已将请求入队，不代表服务端已处理。
    if (!queued) {
      const response = await fetch('/analytics', {
        method: 'POST',
        body: payload,
        keepalive: true,
      })
      if (!response.ok) return
    }

    for (const { id, entry } of batch) {
      // 发送期间更新过的记录留到下一批
      if (logBuffer.get(id) === entry) logBuffer.delete(id)
    }
  } catch {
    // 保留缓冲，等待下次发送
  } finally {
    isFlushing = false
  }
}

setInterval(flush, 3000)

document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') flush()
})
```

性能数据可把[性能指标采集](./性能指标采集.mdx)中的 `recordMetric()` 接到同一个入口。示例在初始化时固定 URL，避免回调在 SPA 路由变化后把指标归到新路由。

```js fold
const metricPageUrl = safePageUrl()

function recordMetric(name, value, details = {}) {
  const { id = name, unit = 'ms', ...extra } = details
  report({
    type: 'performance',
    id,
    name,
    value,
    unit,
    ...extra,
    pageUrl: metricPageUrl,
  })
}
```

`sendBeacon()` 返回 `true` 只表示数据进入浏览器发送队列，代码会移除对应的内存记录，但无法确认服务端是否接收或写入。返回 `false` 时，示例改用 `fetch` 配合 `keepalive`，仅在收到成功响应后移除记录；发送失败则留待重试。这是尽力而为的方案，页面关闭后尚在内存中的记录无法恢复。需要确认送达时，应持久化待发记录，并在服务端确认后删除。

示例最多缓存 200 条，每批不超过 48 KiB；缓存满时丢弃最早记录，单条超限则跳过。应按日志价值调整采样和淘汰策略。Beacon 与 `keepalive` 请求共用 [Fetch 规范](https://fetch.spec.whatwg.org/#http-network-or-cache-fetch)规定的 64 KiB 在途请求体上限，同页其它 `keepalive` 请求也会占用额度。

### 数据脱敏

优先按事件类型白名单选择可序列化字段。`sanitize()` 只按字段名遮盖常见敏感值，无法检查自由文本、Error 的 `message` 和 `stack`，也无法识别 URL 路径中的用户标识。上报前应过滤查询参数并将动态路径映射为模板；服务端也要校验字段。
