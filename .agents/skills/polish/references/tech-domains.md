# 技术正确性检查领域

## 使用方式

领域检查表列出各方向最常见的具体混淆，每一行都是触发器，不是知识边界：命中哪一行，就按行里的对照检查正文；文章主题不在表内时，退回「判别问句」自查，不要因为没命中就跳过检查。

核对结论时取规范、官方文档或运行结果的原文，不把二手摘要当作引文；实测只覆盖测过的那一格，其余仍按文档核准。

## 判别问句

对每个技术断言依次问六件事：

1. **概念同一性**：说的还是同一个东西吗。两个概念是否属于同一层次、同一机制，有没有把阶段、角色、实现方式或相邻概念混成一个；
2. **前提**：结论依赖的版本、运行环境、规模、配置、权限或威胁模型，有没有交代；
3. **因果强度**：相关有没有写成导致，常见做法有没有写成唯一方案，手段有没有写成目标；
4. **顺序与方向**：执行顺序、数据流向、握手与回调时机，有没有写反或漏掉；
5. **量化**：复杂度、量级、阈值、倍率、样本量，有没有依据；
6. **绝对化**：一定、总是、完全替代、无损、跨平台通用这类说法，有没有支撑。

## 处置

- **修正**：能确认的错误直接改，并把结论需要的前提、因果和边界补进正文；
- **标疑似**：无法确认的结论标为"疑似"并写明缺什么，不要换成另一个确定说法。常见触发：
  - 最新版本、浏览器支持、框架 API 变化、模型能力、云服务限制、生态最佳实践；
  - 性能结论没有基准、数据规模、运行环境或对照条件；
  - 安全结论没有说明威胁模型、权限边界或部署环境；
  - 出现判别问句 6 的绝对化表达；
  - 经验判断没有给出场景或约束条件。
- **保留**：面向入门读者的类比可以保留，但不能把类比写成机制本身；
- **不轻信**：代码能运行不代表描述准确，描述准确也不代表代码覆盖了边界，两者分别核对。

## 领域检查表

### 前端基础

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 语言机制 | 检查 this 绑定规则、原型链查找顺序和闭包可达性；不要把事件循环讲成语言规范本身，它是宿主提供的调度机制 |
| TypeScript | 区分类型检查和运行时行为；不要把类型断言说成类型转换；检查泛型、条件类型、类型守卫、声明文件是否有运行时误解 |
| 浏览器机制 | 区分宏任务、微任务、渲染时机和 requestAnimationFrame；不要把 Layout、Paint、Composite 顺序写反；检查 Web API 是否需要安全上下文、权限或用户手势 |
| HTTP 缓存 | 区分强缓存与协商缓存的判定顺序；不要把"加了缓存头"等同于缓存生效；检查 Cache-Control 指令组合、Vary 和 304 的语义是否写清 |
| 存储 | 区分 Cookie、localStorage 与 IndexedDB 的容量、作用域和同步方式；不要把 localStorage 当可靠存储；检查配额淘汰、跨标签同步和序列化边界，Cookie 的安全属性见「Web 安全」 |
| CSS | 检查盒模型、包含块、层叠上下文、BFC、Flex/Grid 规则是否混用；不要把 z-index 问题都归因于数值大小；检查选择器优先级是否准确 |
| React 原理 | 不要把渲染阶段和提交阶段混为一谈；不要把并发渲染理解成多线程并行执行；检查 Hooks 的调用约束、依赖和清理时机的描述是否准确 |
| Vue 原理 | 区分 Object.defineProperty 与 Proxy 两种响应式实现；不要把响应式追踪、虚拟 DOM diff 和编译优化混成同一机制；检查响应式 API 的追踪范围、缓存和副作用边界 |
| 状态与数据请求 | 区分服务端状态与客户端状态；不要把竞态、缓存失效和重复请求归为同一问题；检查乐观更新的回滚、失效时机和订阅粒度 |
| 构建工具 | 区分开发服务器、打包、预构建和 Tree Shaking；不要把开发时免打包等同于产物免打包；检查 ESM、CJS、副作用声明和动态导入的描述是否准确 |

### 微前端

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 沙箱隔离 | 不要承诺沙箱能完全隔离；区分快照、代理和 iframe 三类实现的隔离强度；说明样式隔离在全局选择器和动态注入样式下的失效场景 |
| 集成方式 | 区分运行时集成与构建时集成；不要把模块联邦方案等同于微前端；说明路由分发、公共依赖和版本冲突的处理边界 |
| 应用通信 | 区分 props、事件和共享状态；不要把全局事件总线当作业务状态容器；检查订阅和监听的清理时机 |
| 路由与状态 | 检查主应用与子应用的路由职责划分；说明子应用卸载时事件、定时器和全局变量的释放 |
| 工程约束 | 不要把独立部署写成无代价；说明注册表、版本管理、灰度和回滚的配套要求 |

### 多端

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 运行环境差异 | 区分 WebView、小程序渲染层和原生渲染的机制差异；不要假设 DOM、CSS 和浏览器 API 在每一端都可用 |
| 跨端框架 | 区分编译时转换与运行时桥接；说明框架对原生能力的覆盖范围；不要把"一套代码"写成"一次开发即可完全对齐" |
| 原生桥接 | 说明通信是同步还是异步、是否需要序列化；检查回调丢失、超时和权限申请的处理边界 |
| 样式与布局 | 区分各端的布局单位、安全区域和滚动机制；不要用单一端的适配方案描述所有端 |
| 产物与分发 | 区分分包、预加载和按需下载策略；说明包体积限制、审核周期和灰度发布对方案的影响 |

### 性能优化与监控

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 指标口径 | 区分实验室指标与真实用户指标；不要混用或等同 LCP、INP、CLS、TTFB；说明采集的设备、网络和样本条件 |
| 加载性能 | 区分首屏渲染、可交互和完全加载；不要把懒加载、预加载、预渲染混为一谈；检查资源优先级、缓存策略和预加载范围的描述 |
| 渲染性能 | 区分重排、重绘和合成；不要把防抖、节流当成通用优化；检查长任务、帧率和主线程阻塞的成因 |
| 内存与稳定性 | 区分内存泄漏和内存增长；检查监听器、定时器、缓存和闭包的释放时机 |
| 监控体系 | 区分错误监控、性能监控和业务埋点；检查采样率、上报时机、source map 和告警阈值是否说明 |
| 日志与追踪 | 区分日志级别、采样与成本；检查结构化字段、脱敏和 trace 关联；不要把日志量等同于可观测性 |

### Agent 机制

| 主题 | 高风险检查点 |
| ---- | ------------ |
| Agent 定义 | 不要把 Agent 简化成一次 function calling；也不要把所有带工具调用的聊天都称为完整 Agent；检查是否包含目标、状态、工具、循环和停止条件 |
| Agentic Loop | 区分推理、工具调用、结果回注和下一步决策；不要写成模型真的直接执行了工具；检查错误处理、重试和终止条件是否缺失 |
| 上下文管理 | 不要把上下文窗口等同于长期记忆；区分压缩、摘要、检索和重注入，说明压缩会造成哪些信息丢失；注意 token 窗口不是可无限依赖的存储 |
| 会话与恢复 | 区分会话状态与上下文窗口；检查持久化粒度、恢复点、幂等重放和中断后继续执行的行为 |
| 提示词工程 | 区分系统提示词、用户提示词和补充材料的职责；检查外部内容的信任边界；不要把 JSON 格式约束等同于 schema 或业务校验；区分应用结果缓存和模型服务的上下文缓存 |
| 工具系统 | 区分工具 schema、调用权限、执行环境和结果返回；检查工具是否有副作用、权限控制、幂等性和审计需求 |
| 权限模型 | 检查权限描述是否与具体系统的行为一致（允许、拒绝、询问三类）；不要默认所有工具都能静默执行；涉及文件、网络和命令执行时要说明边界 |

### LLM 应用工程

| 主题 | 高风险检查点 |
| ---- | ------------ |
| LLM 原理 | 不要把 Transformer、注意力机制、上下文窗口和 token 生成混成一个概念；检查 embedding、窗口实际可用长度和幻觉成因的描述是否准确 |
| 模型能力 | 涉及最新模型、价格、上下文长度、工具能力和多模态能力时，核对来源和时间口径；不要把某一版本的能力写成通用能力 |
| 模型训练与推理 | 区分预训练、微调、蒸馏和量化各自的成本与效果；检查 token 计数口径、采样参数与确定性；不要把推理成本等同于训练成本 |
| 检索与向量 | 切分粒度、embedding 模型和查询方式要同源；不要把向量召回等同于语义正确；区分召回、精排与最终上下文组装；说明相似度度量与归一化方式 |
| 流式传输 | 区分 SSE 与 WebSocket 的适用边界；检查断线重连、事件续传和增量合并；不要把流式输出等同于低延迟 |
| 评测 | 区分离线指标与端到端质量；检查评测集是否覆盖真实任务分布；不要把单次对比结论写成通用结论 |

### 后端/全栈

| 主题 | 高风险检查点 |
| ---- | ------------ |
| Node.js | 区分异步 I/O、线程池、Worker Threads 和 Cluster；不要把单线程理解成没有并发；说明它的事件循环与浏览器的事件循环不是同一套；检查 Stream 背压、错误处理和资源释放 |
| 数据库 | 检查索引是否真的能命中查询；区分事务隔离级别、锁、MVCC 和一致性；不要把"加索引"写成万能优化 |
| ORM 与查询 | 区分 ORM 生成的 SQL 与手写 SQL 的执行差异；检查 N+1、懒加载触发时机、事务边界和迁移一致性 |
| 缓存 | 区分缓存穿透、击穿、雪崩和一致性问题；检查过期策略、失效策略、热点 key、缓存旁路和双写一致性 |
| 消息队列 | 区分 at-most-once、at-least-once、exactly-once 的语义；检查确认机制、重试、死信队列、顺序性和幂等性 |
| 微服务 | 检查服务发现、熔断和配置下发是否配套；不要把拆服务直接等同于提升稳定性；分布式事务要说明 Saga、TCC 等适用边界 |
| 并发与幂等 | 区分锁、幂等键和重试各自的职责；不要把重试当作可靠性解法；检查退避策略、超时传递和限流算法（令牌桶、漏桶、滑动窗口）；消息投递语义见「消息队列」 |
| Docker/K8s | 区分镜像、容器、Pod、Deployment、Service、Ingress；不要把容器当虚拟机；检查资源限制、健康检查、滚动更新和配置管理 |
| API 设计 | 检查 REST、GraphQL、gRPC 的适用场景；不要把 RESTful 等同于任意 HTTP JSON；检查版本控制、错误码、幂等性、鉴权和限流 |
| 服务端渲染 | 区分 CSR、SSR、SSG 与增量再生的适用条件；检查水合不一致的成因；说明服务端与客户端的环境边界（全局对象、缓存、请求上下文） |

### Web 安全

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 传输与部署 | 区分 TLS、HSTS、重定向和预载列表各自解决哪一段；不要把「配了重定向」当成传输层防护；检查首次访问、子域范围和证书错误的边界 |
| 同源与跨域 | 区分同源策略、CORS 和代理转发的作用范围；不要把 CORS 当作访问控制手段；检查凭证携带与预检请求的描述 |
| XSS 与注入 | 区分转义、编码和内容安全策略的职责；不要依赖前端过滤；检查富文本、模板和 DOM 操作的注入面 |
| CSRF 与会话 | 区分 SameSite、CSRF token 和来源校验的适用条件；不要把无状态鉴权等同于免疫 CSRF，凭证放在 Cookie 时同样要考虑 |
| 鉴权与越权 | 区分认证、授权和数据过滤的层次；不要把前端隐藏当作权限控制；检查水平越权和服务端校验的边界 |
| 供应链与配置 | 检查依赖来源、锁文件和构建产物的完整性；区分密钥、环境变量和公开配置的暴露范围 |

### 架构

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 分层与边界 | 检查分层依据是职责还是技术栈；不要把目录结构当作架构边界；说明依赖方向是否单向 |
| 模块拆分 | 区分按变化频率、按职责和按团队拆分；说明共享状态归谁管理；不要只写拆分的收益 |
| 数据流 | 区分同步调用、异步事件和共享存储；检查状态由谁产生、谁消费、谁清理 |
| 演进与重构 | 区分重构与重写；说明兼容期和灰度切换的边界；不要把解耦写成目标本身 |
| 结论边界 | 检查架构结论是否写清约束条件，例如团队规模、发布节奏、性能目标，避免写成通用最佳实践 |

### 计算机基础

| 主题 | 高风险检查点 |
| ---- | ------------ |
| 设计模式 | 不要为了套模式而改写问题；检查模式意图、适用场景和代价是否说清楚；区分策略、状态、模板方法、装饰器和代理 |
| 数据结构 | 检查时间复杂度、空间复杂度和操作前提；不要忽略哈希冲突、树平衡、堆性质、图的有向/无向和权重条件 |
| 算法 | 检查边界条件、复杂度、稳定性和最优子结构；不要把贪心、动态规划、回溯、分治混用；示例代码应覆盖讲解所需的关键边界，省略部分要说明简化前提 |
| 网络协议 | 区分传输层与应用层的职责；不要把 HTTP/2 的多路复用写成消除了队头阻塞；不要把 HTTPS 简化成加密的 HTTP，证书校验与握手过程要交代 |
| 操作系统 | 区分进程、线程、协程、并发、并行；检查虚拟内存、文件系统、锁、死锁和调度描述是否准确 |
| 时间与时区 | 区分 UTC 与本地时间；检查夏令时、时区库和序列化格式；不要把时间戳当作本地时间 |
| 编码与 Unicode | 区分字符数、码点数和字节长度；检查代理对、规范化和编码转换的边界；不要把字符串长度当作字符数 |
